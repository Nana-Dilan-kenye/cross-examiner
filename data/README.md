# The data

Everything the agent reads, where it comes from, and what it may be used
for. The registry in `sources.json` is the machine-readable version of
this page; this page is the version a person reads.

## The rule the whole project runs on

A **source** is a publication. An **origin** is the series the numbers
actually come from. A source that republishes another series is a
*derived mirror* of it.

Derived sources are counted once, with their origin. Two sources that
agree because they share an upstream are **one** line of evidence, not
two. That is why the World Bank and the UNICEF data warehouse cannot
confirm the WUENIC estimate: they publish it.

This is recorded in `data/sources.json` and enforced in
`src/critic.py`. It used to be a guess based on the words in a source
name, which meant that renaming a source could change a verdict.

## The synthetic data

`data/synthetic_programme_reports.csv` and `.db` are **generated**. They
stand in for a fictional organisation's district returns so the checks can
be measured: the generator plants contradictions with known answers and
writes an equal number of clean controls, so a false positive is visible.

- Every row carries `is_synthetic=true` and the source label
  `SYNTHETIC district programme reports`.
- The registry marks the origin `synthetic_programme` and the source
  `is_synthetic: true`.
- The generator is seeded, so the same seed always produces the same file.
- The answer key (`eval/answer_key.json`) lists which records carry which
  planted contradiction. **Only the evaluation harness reads it.** The
  application must never import or read it; there is a test that fails if
  anything under `src/` refers to it.

The synthetic records are only read when `--include-synthetic` is passed.
A finding built from them is tagged and can never be disposed of.

## Where the sources are read from

The sources are registered in the Zetaris unified semantic layer, and the
layer is where the application reads them from:

```
lightning.metastore.cross_examiner.coverage_observations.coverage_observation
```

That table holds one row per reported number with the lineage of the
row: the source and its type, the series the number comes from, whether
it is a derived copy, whether it was generated, and how far it may be
trusted as evidence. `data/sources.csv` is the same registry flattened
into a table, and `data/registry/` holds the SQL that builds the layer.

The compiled sheet is the one source whose *transport* and *origin*
differ: the numbers are transcribed from the DHS Program's published
report, and the report is where the series is published, but they are
served through the project's evidence API because the filestore
connector on this instance only accepts `s3a://` paths.

## The measurement kinds

| Kind | What it means | Example |
|---|---|---|
| `reconciled_estimate` | A reconciliation of administrative, survey and other evidence. | the WUENIC estimate |
| `administrative_reporting` | Facility and district reports against a population denominator. | the administrative figure |
| `government_estimate` | The national government's own estimate. | the official figure |
| `household_survey` | A sample of households. | the DHS figure |
| `synthetic` | Generated. | the district returns |

Only `household_survey` is independent of the administrative reporting.
That is the whole reason the survey line is worth carrying: it is the one
number in the project that does not come from the same reporting the
administrative figure comes from.
